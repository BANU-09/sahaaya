## Issues found and resolved

- Corrected low-contrast text and the mobile Easy Mode button's missing accessible name; full feature and mobile axe checks now pass.
- Corrected a locale synchronization issue that could overwrite a new language selection; all six language selections and reload persistence pass.
- Removed vulnerable/unused dependencies, upgraded Prisma and the test runner, and pinned a patched compatible transitive minimatch dependency; both final npm audits are clean.
- Replaced the initial lightweight PGlite development database after concurrent web/worker requests exposed protocol errors. The old data/settings remain preserved privately; native PostgreSQL is now active. The complete suite passed again against native PostgreSQL, followed by 50 successful concurrent/sequential dashboard measurements with the worker running.
- Added explicit consented profile creation for Google-only/new family accounts, draft editing, as-needed dose replay protection, notification categories, and paged scheduler traversal.

## Remaining work and practical limits

The complete requested scope is larger than the delivered implementation; [REQUIREMENTS.md](docs/REQUIREMENTS.md) is the detailed gap list. Significant remaining feature work includes dedicated barcode/packaging and lab-report extraction, PDF OCR, AI-assisted write/draft tools, structured shift-handover reports, custom-range/heatmap/vital-trend analytics and optional SMS. Existing forms and protected uploads support the corresponding manual records where described.

Before real patient use, finish remaining live provider acceptance and public deployment, verified email/mobile ownership and MFA, upload malware scanning, data export/deletion/retention operations, operator privacy/grievance details, clinical/native-language copy review, independent security/accessibility assessment, managed-PostgreSQL load/chaos testing and a backup/restore drill. The privacy explanation is currently English. Source medical instructions preserve their original wording; app translations have not been clinically reviewed.

Additional limits: family synchronization is 15-second visible-tab polling; Calendar sync is user-triggered; active medication changes require a newly approved draft; dashboard collections are bounded; a scheduler transaction has a 60-second deadline; CSP permits inline Next.js scripts/styles; no private offline medical cache is provided. Local tests do not establish production capacity, regulatory compliance, emergency-service reliability or medical efficacy.

## Reproduction and artifacts

Follow [README](README.md) for native DB, environment, migration/seed, web and worker commands. Stop the standalone worker before running API tests that manipulate scheduler time. Run tests only against disposable fictional data. Run `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run test:coverage`, `npm run build`, then `npm run test:e2e` against the running production server. Start the worker afterward and run `npx tsx --env-file=.env scripts/measure.ts` for the local measurement.
